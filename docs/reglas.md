# A3 - Reglas del caso

## Reglas funcionales

1. Los códigos de emprendedores, iniciativas y asesorías deben ser únicos.

2. Cada iniciativa debe tener un emprendedor responsable existente.

3. Un emprendedor puede ser responsable de varias iniciativas.

4. Cada asesoría debe estar asociada a una iniciativa existente.

5. Cada asesoría debe registrar el código ficticio del asesor que la atiende.

6. Los sectores de ejemplo son:
   - tecnologia
   - alimentos
   - economia_circular

7. Las etapas didácticas de las iniciativas son:
   - idea
   - validacion
   - puesta_en_marcha

8. El estado de una iniciativa puede ser:
   - activa
   - archivada

9. El estado de una asesoría puede ser:
   - programada
   - realizada
   - cancelada

10. Cada asesoría debe registrar una fecha_programada.

11. Cuando una asesoría se realiza, se debe registrar la fecha_realizacion.

12. La fecha_realizacion puede ser diferente a la fecha_programada si hubo una reprogramación.

13. No se debe modificar la fecha_programada para ocultar una reprogramación.

14. No se deben programar dos asesorías para el mismo asesor en la misma franja horaria definida para el laboratorio.

15. Archivar una iniciativa no elimina automáticamente su historial de asesorías.

## Preguntas para la persona responsable de la Unidad de Emprendimiento

1. ¿Qué información específica necesita consultar con mayor frecuencia sobre cada iniciativa?

2. ¿Qué duración o franja horaria se debe utilizar para evitar que un mismo asesor tenga dos asesorías programadas al mismo tiempo?

## Riesgo identificado

Un riesgo es que se registren asesorías duplicadas o en horarios que se crucen para un mismo asesor, lo que puede generar errores en la programación y dificultades en el seguimiento de las iniciativas.

## Justificación

Estas reglas permiten mantener organizada la información de emprendedores, iniciativas y asesorías. También ayudan a evitar duplicados, relaciones con datos inexistentes y conflictos de horarios.
